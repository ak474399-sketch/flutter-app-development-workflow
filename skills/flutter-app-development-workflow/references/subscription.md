# 可选订阅模块

## 模块能力与边界
本模块面向 AI 订阅类产品，保留页面、入口、交互及状态经验。`assets/sdk/app_subscription_sdk` 提供真实商店客户端适配、购买／恢复状态机、订阅 UI 与 HTTPS 权益验证调用。商品和验证后端由各项目独立准备，客户端实现不等于真实收费链路已验收。

关闭按钮延迟2秒、购买及恢复验证成功且权益生效后自动关闭，是本流程已确认默认规则。当前 SDK 与自动测试提供规则实现依据；历史页面演示和模拟权益不替代真实 Billing／恢复验收。

## 默认页面与交互
订阅被选用时，默认采用以下结构，先输出代表订阅页供用户验收，再实现完整状态。品牌、价格、商品数量及周期由本产品确认。

| 区域 | 默认结构与细节 | 来源／可配置项 |
|---|---|---|
| 整体 | 全屏页面，上方主视觉，下方权益、套餐、主按钮及法律链接 | AI 订阅类默认结构；不固定成所有屏幕相同比例 |
| 主视觉 | 原创／有授权的图片或视频；视频静音循环，失败回退静态图，减少动态效果时暂停 | 已有实现；素材与品牌重新制作 |
| 关闭 | 左上圆角 Material 关闭图标，默认 32dp 图形、48×48dp 点击区；深色主视觉上用白色，保证可辨识 | 已有代码样式；颜色随已验收背景适配 |
| 恢复 | 右上文字按钮，透明背景、下划线，点击区至少 48dp 高 | 已有结构；文案本地化，真实恢复能力另接 |
| 套餐 | 单列互斥卡片，选中状态有主色描边与浅色填充；标题、价格／周期清楚对应 | 已有结构；不默认沿用旧商品、试用或价格 |
| 购买 | 明确的宽胶囊主按钮；加载、不可购买、处理中均有可辨识状态 | 已有布局；接入真实购买状态 |
| 底部 | 条款、隐私、订阅说明等本产品实际链接 | 链接可用、文本准确、不会挤出安全区域 |

图标先保持语义占位；主视觉按已确认风格独立 image 制作。购买控件、价格和文字用 Flutter 渲染，不能嵌入一张不可交互的设计图。小屏、大字、长译文时减少主视觉占比，让套餐区可滚动，不锁死卡片高度；法律文字保持可读。默认左右内容间距参考 20dp，实际适配在页面验收中确定。

### 关闭按钮 2 秒规则
- 从订阅页首次可见帧开始计时，默认 2000ms 后显示；不等待图片下载、视频初始化或商品加载完成。
- 前 2 秒按钮不可见、不可点、不可聚焦，无关闭按钮的读屏节点；预留位置，出现时不挤动恢复按钮或其它内容。
- 普通重建、切换套餐、价格刷新不重置计时；销毁页面取消计时，新进入的一次页面会话重新计时。
- 点击关闭仅执行一次，目的地依据入口：引导入口按已确认引导路径继续；功能入口返回原流程；无返回栈使用已确认回退路径。SDK 不硬编码旧应用路由。
- 该要求针对页面关闭按钮。系统返回／返回手势以及购买中退出行为在本产品交互表中单独确认，不能自行增加强制停留或屏蔽退出。

### 购买与自动关闭
状态至少区分：商品加载、可购买、发起购买、商店 pending、交易验证、权益生效、取消、失败。只有**交易已经确认且权益已经生效**，才更新全局权益并自动关闭当前订阅页；仅收到按钮点击、商店购买回调或本地模拟成功均不满足条件。

防重复点击和重复回调；同一交易幂等更新权益，同一页面最多执行一次成功关闭。关闭后原页面读取新权益，不再弹同一付费拦截。pending／验证失败／取消保持可恢复的页面状态，不误报成功或自动关闭；已离开的页面收到异步回调时更新合法权益，但不操作已经销毁的路由，也不误关其它页面。支付成功关闭不等待 2 秒按钮计时。

恢复购买需真实查询并验证交易，不能直接赠送会员。用户已确认：恢复购买经验证且权益生效后同样自动关闭一次；未找到购买、验证失败和恢复 pending 不自动关闭。已拥有有效权益时如何跳过订阅页同样根据入口合同确定。

## 准备与对齐
核对参考的订阅页面和可观察行为，按用户新决定整理商品表：商品ID、周期、权益、试用／优惠、免费范围、订阅入口与关闭路径。价格来自本产品商店实际商品，不照抄竞品地区价格。准备商店账号／应用身份／测试购买资格，必要的交易验证和权益后端。

## 接入工作
1. 按已确认设计实现订阅页、商品加载／失败／不可购买状态。
2. 选受支持商店购买插件／官方接口；查询商品，处理pending／成功／取消／失败。
3. 验证交易，幂等授予权益，完成商店要求的交易确认；客户端成功回调不独立证明服务端权益。
4. 恢复已有购买、重启恢复、过期／退款／撤销及网络失败按实际平台合同处理。
5. 已确认购买事实才发金额事件；自动事件和手工上报避免重复。商业化可选关闭时不得建立假购买或赠送真会员。

推荐参考 [Flutter官方购买插件](https://pub.dev/packages/in_app_purchase)，执行时核对平台当前文档。商品、账号和服务端验证资料按项目准备。

## 产物与验收
商品／权益表、页面流程、接口与事件映射、客户端及验证后端、商店测试结果。验收不能只检查截图，至少包含：

| 用例 | 通过条件 |
|---|---|
| 首次显示至 1999ms／2000ms | 前者没有可用关闭按钮，后者出现且可点击；布局稳定 |
| 重建／套餐切换／退出再进入 | 当前会话不重计时；退出无计时泄漏；新会话重新计时 |
| 小屏／大字／长文案／RTL | 主按钮、套餐、关闭与法律链接可操作，价格及文字未裁掉 |
| 各入口关闭 | 回到约定目的地一次，原流程及未提交内容保持正确 |
| 购买 pending／失败／取消 | 不授予权益、不误关页面，可按合同恢复或重试 |
| 已确认购买且权益生效 | 更新权益后自动关闭一次，原页面即时获得正确权限 |
| 重复回调／离页后回调 | 无重复发权益、重复跳转或误关新页面 |
| 恢复／重启／到期／退款撤销 | 真实交易与权益一致，恢复关闭行为符合已确认合同 |

用户验收实际链路。页面演示、商店测试购买、真实收费与正式发布分别标注。自动测试不能证明真实扣款或后端权益到账。
