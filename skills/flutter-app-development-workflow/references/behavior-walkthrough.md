# 行为走查与执行验证

本文件保留 v0.1.0 的同agent历史走查。2026-10-10 的缺陷修复和独立agent实际引导验证见 [本轮报告](evaluations/20261010/report.md)，不将两种方法混计。

方法：本 agent 按最终 skill 对以下测试输入逐项走查，结合可执行检查器的15项正／负用例；未调用独立 agent，未测试其它模型。本文件不是用户对新产品的验收。测试中的“用户确认”是隔离夹具，不能录入真实项目。

| 测试输入 | 实际走查输出／判断 | 执行证据 |
|---|---|---|
| 只有 APK 包名，没有可取得的样本／报告 | 首次先给十阶段概览；当前是阶段1，缺样本与报告版本。只问是否能使用已有报告或取得授权样本；不补目标用户／市场定位，不宣称识别出全量页面。 | stage-prompts 第1节；空模板结构检查通过，但 `--for-stage 1` 因 scope／criteria 空而拒绝开始。 |
| 报告只有主流程，没有恢复页与失败状态 | 阶段2清单把这些分支标待验证；给“补取证／用户明确设计新分支”的选择，后者标新决定。设计图不能记为运行观察。 | 来源映射、未知页面、占位图片的负用例均被检查器拒绝。 |
| 用户只说“这个设计方向可以” | 只可继续已授权设计，不登记阶段完成；向用户展示实际产物、版本、覆盖／缺口后再验收。 | `test_plan_approval_is_not_stage_acceptance`：仅有方案 quote 不能使阶段2开工。 |
| 缺 Firebase／Meta 配置、订阅商品或后端 | 可编译真实客户端、做替代适配器测试和 UI 演示；明确后台／商店未验。不默认授予同意，不造后台事件、付费权益或广告收入。 | 基础 consent 门槛、未选广告零初始化、订阅失败／pending／无效权益测试。示例始终标模拟。 |
| 用户修改已验收 UI 范围，随后跨会话续办 | 保留历史记录，revision 更新；受影响验收失效。读取交接和现行记录，先核当前产物，不重问可查决定，也不继承旧版本证据。 | stale revision、产物哈希变化、依赖未验收、缺实际确认定位的负用例拒绝。 |
| 用户不选商业化，或项目无后端功能 | 商业化关闭；必选基础 SDK 保留。无后端阶段列不适用原因并由用户确认，不强行创建后端。 | 必选模块禁用负用例；not_applicable 必须有原因及用户确认记录。 |
| 真机不可用，且设备含已有数据 | 不自动擦除／覆盖；将已获授权的数据保护与设备操作作为条件分支。模拟器结果与真机检查分别记录，不阻断可独立的代码工作。 | 来源案例 ad-device-conditional；走查确认没有通用强制备份阶段，未启动真实设备。 |

引导模板有明确的 agent 自查项、用户决定项、推荐／影响示例和阶段产物。人工检查其保持了已有 APK／报告为入口、没有自行增加人群或付费理由、没有把假数据作为业务事实。该走查不证明所有模型都会遵守；后续真实调用发现的失败应只针对证据修正。

复验：`python3 -m unittest discover -s tests -v`；三个 SDK 各运行 `flutter test --reporter expanded`。格式校验和机器结果都不替代真实用户的阶段验收。
