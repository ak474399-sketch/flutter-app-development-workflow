# 可选 IAA 模块

## 实际基础
AI 英语已有 `lib/ads.dart`、原生桥接、`AdPolicy`、共享缓存、布局及激励验证实现，但绑定具体业务与配置。本次用户要求将请求、缓存、展示机制作为所选 IAA 模块的默认实现范围。本次已新增 `assets/sdk/app_iaa_sdk` 的库存状态机和真实 Google Mobile Ads 适配器，附替代适配器测试及接入说明。这是本次新实现，不是旧代码原样抽出或正式投放已验收。

来源：`docs/ADS-FIREBASE-PRODUCTION-20261007.md` 与当前 `lib/ads.dart`。最新正式英语包已关闭广告运行；以下机制来自之前接入记录，仍需在新项目重新验证。

## 默认机制与项目配置
订阅与 IAA 仍分别可选。选用 IAA 后复用机制，未选 IAA 时不初始化、不请求、不展示。用户已确认复用请求／缓存／展示机制，只启用新产品实际选择的格式；具体页面触发时机与频率逐项目对齐。下面容量、有效期和并发上限已确认作为本 skill 默认值，加载／启动超时与退避值沿用英语的配置起点，执行时核对适用性。

| 项目 | 默认值／规则 | 新产品需准备 |
|---|---|---|
| 共享库存 | 同格式的业务位置借用唯一 SDK 对象，不按每个页面建池 | 广告类型、业务位置→物理池映射 |
| 池容量 | 每池 ready＋pending 最多 2 条；两个插页池合计最多 4 条 | 所选格式、单元数；不用的格式不请求 |
| 单元安排 | 英语曾使用每池两个不同单元各一条，六池共 12 条 ready | 本产品自己的单元；不复制旧账号 ID 或强制六池 |
| 并发 | 全局最多 4 个加载请求 | 按真实网络与设备验收；不得无界并发 |
| 有效期 | 缓存 55 分钟到期，借出前再次校验 | 按所选 SDK 当前有效期复核 |
| 请求时限 | 每次加载 25 秒；启动等待总预算 10 秒，初始化计入同一预算 | 启动与页面失败后的业务去向 |
| 失败重试 | 英语为 5／10／15 秒退避，连续失败后冷却 300 秒；禁止无限即时重试 | 按产品确认恢复触发和请求预算 |
| 补请求 | 初始化后预加载启用池；消耗／释放后补库存 | 只补库存，不因补成功自动弹广告 |
| 页面条件 | 前台、页面仍有效、机会仍有效、未被其它全屏广告占用 | 页面生命周期与业务机会合同 |
| Banner 刷新 | 使用广告平台／SDK 配置，客户端不另建 10 秒刷新循环 | 后台刷新设置与真实行为核验 |

英语引导前进、翻译、Tab 计数等是具体产品触发记录。新产品在页面与交互阶段确认自己的入口与频率；不要从缓存默认值推导“每次点击都弹广告”。若采用英语触发预设，逐项列出处与规则，冲突时按用户已确认指令对齐，不能仅以当前代码覆盖真实需求。

## 请求→缓存→展示状态合同
1. **初始化**：核对启用状态、同意状态、测试／正式单元和参数合法性。关闭构建有本地硬开关，Remote Config 不得重新打开。初始化失败不阻断核心功能。
2. **请求**：按池优先级、ready＋pending 容量和全局并发预约槽位；同槽位不能重复请求。结束、异常和超时均释放 pending 计数并进入有限退避。
3. **接收**：每次配置替换、关闭或销毁增加库存代次。加载成功必须仍属于当前代次、有效配置和启用池；旧请求迟到只释放对象。超时不是底层 SDK 已取消，迟到成功仍须释放，不进入新缓存。
4. **缓存**：对象仅在内存，记录加载时间、格式、池、单元槽位、代次。过期、关闭、配置变更或销毁时释放；不备份 SDK 对象、广告令牌或库存。
5. **取用**：借出前校验有效期及业务条件；对象唯一租用。Banner／原生租约绑定实际可见容器，不能同时装到两个视图；释放后不可重新复用一次性对象。
6. **展示**：全屏广告全局互斥。无缓存／失败直接返回明确结果，让原流程继续；除已确认的启动等待合同外，临时页面不等待将来广告、离页后不补弹。
7. **结束**：关闭、展示失败或异常均释放对象、解锁互斥并补库存；一次机会只结束一次。展示结果明确区分未就绪、失效、失败、已关闭和 earned，不能用同一个 true 表示广告完成与权益到账。

冷／热启动默认机制可复用英语“开屏优先，仅无可用开屏时考虑已缓存插页”。插页回退属于需确认的产品策略，执行接入时核对当前广告平台规则与实际启动场景，不把它自动强加到所有新产品。广告引发外跳或返回时抑制重复热启动展示；真正恢复前台按合同重新判断。广告出现和关闭不能清空草稿、录音或下载状态。

## 布局与激励
原生／Banner 容器与继续、关闭、导航、输入区分别布局，广告标签和广告 CTA 遵循实际 SDK 要求；禁止把业务按钮覆盖在广告上。参考英语已验证过的方案：固定预留区域、至少 16dp 分隔、绘制和触摸区域裁剪、键盘展开隐藏原生、离页释放租用。具体高度、位置和颜色在本产品页面验收中确定，300dp 不是通用强制值。

激励状态为准备→展示→客户端 earned→服务端验证→领取／pending→权益生效。仅 earned 不代表到账。提前关闭、重复回调和重试不能多发奖；恢复持久化回执，不持久化广告对象。奖励内容、限制、真实身份及 SSV 配置由项目准备，旧项目奖励数量和地址不进入通用默认。

## 准备与对齐
从报告／运行证据提取广告入口，用户确认采用哪些。建立“业务机会→格式→广告单元→缓存池→触发／频率→失败行为→奖励”表；明确开屏、插页、原生、Banner、激励的实际位置与退出行为。广告ID、缓存数量、时长、奖励数和频率均重新配置，历史数值只作来源明确的案例。

## 接入工作
- 用官方测试单元完成开发；正式ID由正式配置注入。
- 生命周期统一：初始化、预加载、ready／pending容量、展示租用、互斥、过期、释放与补请求。
- 展示前确认仍处于对应页面／业务机会；异步迟到不补弹，失败或无填充按已定规则恢复业务。
- 原生／Banner使用实际SDK视图；固定区与继续按钮／键盘／导航独立布局，验证绘制及触摸边界。标签和CTA由SDK规范处理。
- 激励观看完成、后端签名验证、领取回执与最终权益分别处理；提前关闭／重复回调／重启不多发奖。客户端回调不替代正式SSV。
- 广告关闭时停止初始化、请求、展示及远端重新开启；SDK是否仍在包内单独报告。
- 收入事件使用SDK返回的真实金额／币种／精度，不能用展示计数乘估算金额当收入。

## 验收
缓存容量（含 pending）、并发上限、过期、唯一租用、有限退避、超时迟到释放、关闭后无新请求、配置变更后无旧库存；全屏互斥、缺货／失败放行、回后台／返回、草稿保护；正常／长文案／小屏／大字／键盘广告避让；激励完成／取消／重复／pending／到账；测试正式隔离。记录实际请求、库存变化、展示和释放证据。正式填充、SSV 真实签名回调、实际权益和收入归因独立验收。

参考 [Google Mobile Ads Flutter](https://developers.google.com/admob/flutter/quick-start)。旧项目使用原生桥接，本次通用模块采用官方 Flutter 插件，不能把新适配和旧原生桥接当成相同已验实现。
