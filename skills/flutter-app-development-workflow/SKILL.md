# Flutter 应用开发流程

## 入口与第一次回复
先读已有项目说明、用户指令、逆向报告、页面证据、版本记录及验收材料。核心入口是参考 APK／逆向资料；没有资料时说明缺口并询问可取得的来源。不要自行加入市场定位、目标用户访谈、付费理由等通用策划步骤。特定人群、价格或商业规则只来自明确用户决定。

首次调用必须向调用者直接展示下表，说明每阶段要做什么、需要准备什么、产出什么及如何验收。随后指出当前阶段、已可复用材料和当前缺口，提出当前阶段少量关键问题。不要只说“我将制定计划”。

| 阶段 | 工作 | 准备材料 | 主要产物与验收 |
|---|---|---|---|
| 1 参考资料 | 获取并核对样本和记录 | APK、逆向报告、开发记录、来源 | 资料清单、版本、证据范围和缺口 |
| 2 页面与交互 | 整理入口、流程、操作和状态 | 报告、运行证据、用户修改指令 | 页面／流程／交互清单、用例；来源明确、分支可追溯 |
| 3 页面设计 | image 代表页确认后扩展 | 页面清单、文案、指定风格和品牌 | 页面设计图；用户确认代表页，再覆盖已定页面及关键状态 |
| 4 Flutter UI | 可交互页面及素材替换 | 已确认设计、路由、素材位置 | 先 icon 占位后 image 替换；主流程、二级页、状态及交互验收 |
| 5 本地内容与功能 | 内容校验、接入和本地业务 | 内容来源、结构、规则、交互用例 | 内容完整度、真实本地闭环、保存／恢复／失败证据 |
| 6 后端交互 | 必要接口、存储、分发与联调 | 接口范围、配置位置、数据规则 | 客户端→后端→页面结果；错误、重试与幂等验收 |
| 7 AI 服务 | 模型、提示词、输出与调用编排 | 已确认 AI 范围、模型、输入输出合同 | 真实输入／输出及失败恢复；内容生产和运行时 AI 分验 |
| 8 SDK 与商业化 | 默认基础 SDK；选用订阅／IAA | 独立配置、事件表、可选商业规则 | Firebase／Facebook 后台证据；所选商业化链路验收 |
| 9 整体验收 | 当前版本回归与缺陷修复 | 候选版本、用例、适用设备 | 分层证据、缺陷闭环、未验项和用户验收 |
| 10 上报与交付 | 素材、构建、交接及约定提交 | 已验收版本、真实截图、发布资料 | banner、logo、上线图、文案、源码、包、哈希；各自验收 |

详细阶段准备、提问与门槛见 [阶段规范](references/stages.md)。提问方法见 [引导与验收](references/guidance.md) 和 [各阶段问题模板](references/stage-prompts.md)。历史依据见 [经验与来源](references/experience.md)，逐项摘录及定位在 `references/source-index.json`。仅加载当前阶段相关内容。

## 大阶段门槛
执行前与用户对齐阶段范围、准备内容及具体验收标准。大阶段结束展示产物、实际证据、缺陷与未完成项，获得用户明确验收后才进入依赖它的下一阶段。自动检查是证据，不替代用户验收；等待用户时可继续整理独立材料。未通过不登记完成。无对应需求时说明原因，请用户确认不适用。阶段内操作不重复询问已授权决定。

用 `assets/templates/project.json` 建立当前项目状态，产物使用相对项目路径和 SHA-256；验收绑定范围版本、明确用户原话及时间。阶段变更后撤销受影响验收，保存历史。用 `assets/templates/acceptance.md` 展示验收卡；`scripts/check_workflow.py` 检查依赖、资料映射、文件哈希和验收记录；它不能证明业务、视觉或用户同意事实。

十个阶段及相邻阶段的验收依赖保留在清单中；不适用阶段使用带原因和用户确认的 `not_applicable`，不能删除阶段或移除依赖绕过验收。revision 为正整数；准备门槛要求 scope 和每条 criteria 为实际非空文字。独立材料准备可以并行，但不将其登记为已经进入依赖阶段。

## UI 与事实边界
报告、截图、设计板、Flutter 运行图和商店图分别记录。页面／状态／控件不要混算为页面数量。每个页面、交互、功能标注来源：静态确认、运行观察、用户决定、推断或待验证。未观察分支列缺口；不得将生成设计图或自行设计写成竞品事实。

先明确页面和交互，再做设计、可交互 Flutter UI；正式功能开发前补交互用例。插画、品牌及大入口位置先占位再独立 image 生成，素材按用途映射；返回、关闭、播放等操作图标保留清晰语义。设计图只作参考，文字及控件用 Flutter 实现。图片工具不可用则保留待完成项，不能画个占位后登记已完成。可用 imagegen 时使用它；Figma 或设计类 skill 只在有对应资料和工具时使用。

## 默认 SDK 和可选商业化
Firebase Analytics、Crashlytics、Remote Config 与 Facebook App Events 为本用户流程的必选模块。Facebook 范围为安装／启动与应用事件，商业事件由所选模块补充。SDK 收集状态依据项目隐私和同意决定；集成必选不等于自动授予数据采集同意。

订阅和 IAA 各自可选，也可都选或都不选。准备 [SDK 接入规范](references/sdk.md)，按需读 [订阅模块](references/subscription.md) 或 [IAA 模块](references/iaa.md)。共享 Android-first 实现位于 `assets/sdk/app_growth_sdk`；可选广告模块为 `assets/sdk/app_iaa_sdk`，可选购买／恢复及页面模块为 `assets/sdk/app_subscription_sdk`。各包附接入说明与测试，共同模拟演示／原生编译宿主为 `assets/sdk/example_app`。客户端适配与状态机不等于真实后台或商店链路通过。iOS 原生 Meta 适配尚未实现，显式记为缺口，不将 Android 检查继承给 iOS。

选用 IAA 后默认沉淀请求、共享缓存、展示互斥、过期释放、补请求、失败放行及迟到回调处理；池容量与触发规则按 IAA 合同确认。选用订阅后默认沉淀主页面布局、关闭按钮样式及首次可见帧起 2 秒后显示、交易确认且权益生效后自动关闭。已实现代码与规则合同分别登记，不能用 mock 购买或测试 earned 代替实际权益。

每个产品、平台和环境填独立配置。无正式配置时可完成代码和隔离测试，正式接入验收保持待完成。历史包名、服务器、密钥、广告 ID、价格、事件正文及真机资料不进入模板。将“已接 SDK”“后台收到事件”“归因结果”“收入／权益到账”分别验收。

## 上报与续办
读取 [素材与交付规范](references/delivery.md)。上报前生成 banner、logo／图标及真实 UI 上线图，文案逐项绑定实际功能和候选版本；设计阶段先定品牌方向，最终导出在版本验收后完成。商店当前规格执行时核对官方来源，不能固定沿用历史尺寸／政策。

按约定交付源码、配置模板、测试定义与结果、可编辑素材、版本包及哈希、交接和缺口。只有明确要求才提交商店；正式构建、上传、审核、上线分别记录。设备已有数据时才进入保护与迁移分支，备份流程不是通用主阶段。

结束或交接时记录当前阶段、最新决定、产物版本、已验范围、缺口和下一步。续办重新核对易变状态，不重做已验产物，不继承旧版本验收。

## 可执行检查与边界
从模板复制 project.json 到新项目，先填 scope、criteria、inputs，再用 `python3 scripts/check_workflow.py <项目清单> --root <项目根> --for-stage <阶段ID>` 核对依赖与准备；只查清单可省略 for-stage。status 为 pending 的空模板可通过结构检查，但不代表可开始工作。accepted 必须填写实际用户 quote／message_ref／time／revision 及产物 file／sha256；脚本不验证用户原话的真实性。完整开发记录的文件库存位于 `assets/evidence/development-record-inventory.json`，它不代表全部会话逐字阅读。

素材导出使用 `assets/templates/exports.json` 和 `scripts/check_exports.py`，当前支持 PNG 结构、尺寸、alpha 通道及精确平铺 ZIP 内容，不解码像素、不判断视觉或商店当前规格。实际行为演练和验证边界见 [验证记录](references/validation.md)。
